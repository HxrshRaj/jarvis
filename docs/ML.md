# ML & deep learning: the task-router experiment

Problem: label a request with one of 8 routes (general question, research, coding, document analysis, data analysis, memory
retrieval, voice command, tool execution). The label is **informational and never authorises anything**.

## Reproduce
```bash
cd backend
pip install -e ".[dev]" --extra-index-url https://download.pytorch.org/whl/cpu
python -m ml.train        # regenerates ml/data, ml/artifacts, ml/reports (about 30 s on CPU)
```
Outputs: `ml/data/intents.csv`, `ml/data/natural_test.csv`, `ml/artifacts/{sklearn_router.joblib,torch_router.pt,router_meta.json}`,
`ml/reports/results.{json,md}`. Every reported number is generated by this script (a test re-computes one from the artifact).
MLflow was **not** used; results are JSON/Markdown files committed to the repo.

## Data (synthetic, with leakage controls)
- 8 classes × 14 hand-written templates × slot fillers. Splits are by **template** (10/2/2) and by **filler pool** (60/20/20), so no
  template or filler is shared between train and test; `validate()` asserts this and a test proves leakage is detected.
- `natural_test` (64 examples) is hand-written independently of the templates and checked for non-overlap.
- Limitation: synthetic data. Absolute scores say little about real users.

## Models
1. **Rules baseline** (regexes in `app/ml/router.py`).
2. **scikit-learn**: TF-IDF (word 1-2 + char 2-5 n-grams) → logistic regression; `C` chosen on validation only.
3. **PyTorch** (CPU): hashed word/bigram/char-trigram `EmbeddingBag` → MLP; AdamW, early stopping on validation macro-F1, fixed
   seeds + deterministic algorithms, best-checkpoint saving/loading (`weights_only=True`), 5 seeds reported. This is a tiny text
   classifier trained from scratch — **not** a language model.

## Results (from `ml/reports/results.md`)
| model | held-out-template macro-F1 | hand-written macro-F1 |
|---|---|---|
| rules | 0.469 | 0.304 |
| scikit-learn | 0.412 | 0.710 |
| PyTorch (5 seeds) | 0.404 ± 0.083 | 0.491 ± 0.014 |
| hybrid (sklearn if confident, else rules) | 0.715 | 0.770 |

Grouped 5-fold CV (by template): rules 0.419 ± 0.130, scikit-learn 0.906 ± 0.073.

How to read this honestly:
- The held-out-template split has only ~16 effective samples (errors cluster by template), so its numbers are noisy; grouped CV and
  the hand-written set are more informative. No significance tests were run.
- The scikit-learn model clearly beats the rules, and the **hybrid policy** (the thing the app would actually run) beats rules on both sets, so
  the classifier is kept — as an **optional** component: `JARVIS_ROUTER=model` (default `rules`; the app works with no artifacts).
- **The PyTorch model did not beat the classical baseline** (0.49 vs 0.71 on hand-written). With ~300 training examples that is expected;
  it is shipped as an experiment, not used by the router unless `JARVIS_ROUTER_MODEL=torch`.
- The confidence threshold (0.2) was selected on grouped out-of-fold predictions, not on the natural test set.
- Because the router label does not influence tool choice or approvals today, the practical benefit is currently limited to the UI label and
  future routing; a test proves a wrong label cannot bypass approval.
